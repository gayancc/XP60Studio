# Phase 4 live audition implementation

Software implementation and FakeXp60 regression evidence; physical acceptance
is deferred to the separate manual XP-60/WIDI Master verification task.

## User workflow

Editing stays local by default. After a successful temporary-Patch fetch, use
**Arm**, then **Start live audition**. This explicitly authorizes subsequent
edits, Solo/Mute and A/B changes to the temporary Patch for this connection.
Starting captures the current instrument Patch as a safety snapshot.

- **Stop & keep B** sends the unmasked working Patch, reads it back, then exits
  live mode. A/B returns to B and Solo/Mute flags clear. Edits made while stopping
  remain local; the final target is captured when Stop is pressed.
- **Restore before audition** restores the captured pre-audition Patch and
  verifies it. Local edits and undo history remain available.
- **Stop now** cancels pending updates and transfers immediately. It does not
  silently send a restoration. The temporary Patch may be partly updated; the
  transfer status states that uncertainty and retains the safety snapshot.
- Disconnect, device-ID change, transport failure, read timeout or mismatch
  terminates audition. It never resumes or retries writes automatically.

There is no permanent User-memory write path here. Audition flags are an overlay
on the selected A/B Patch, not saved Tone switches and not undo entries. Disabled
Tones are not forced on by Solo. No MIDI note generation or software synthesizer
is implied; play the XP-60 to hear the audition.

## Implementation

`PatchTransfer` owns the live authorization, original safety snapshot, one active
transfer and at most one pending desired Patch. A 120 ms timer coalesces edits.
While a send/read-back is active, subsequent edits replace the pending target.
The visual model responds immediately; it does not wait for MIDI.

`Xp60PatchCodec::encodeChangesToDataSets` compares encoded blocks and sends
changed spans at documented offsets. Span and packet boundaries preserve entire
encoded parameters, including two-byte nibble values. Messages obey the selected
transport payload cap and pacing. Unchanged blocks are not sent.

Each update is followed by a complete five-block read-back and byte comparison.
The next update is calculated against that verified result. This prioritizes
integrity over maximum refresh rate; audible latency depends on the interface,
pacing and full-read round trip. A 120 ms coalescing window is not a measured
hardware latency guarantee. Physical tests must determine acceptable behavior
on both wired and WIDI links.

Diagnostic reads, connection tests, independent Patch writes and pacing changes
are disabled in the Devices view while audition owns the transfer. Disconnect
remains available. The editor distinguishes LIVE / PENDING from LIVE / VERIFIED;
transmission alone does not establish verification. Transfer-owned reads never
replace the local A/B copies or undo history.

## Effects metadata and routing evidence

`Xp60Effects.h` transcribes all 40 EFX type names from the official
[Roland XP-60/XP-80 Owner's Manual](https://cdn.roland.com/assets/media/pdf/XP-60_80_OM.pdf),
printed pp.199-203 (PDF pages 201-205). Raw values 0-39 map to the printed
1-40 types using MIDI Implementation p.223. Effects and Expert share the same
catalog; unknown values retain a numeric fallback. Series (`->`) and parallel
(`/`) names remain distinct. This does not change the generated byte layout,
numeric raw ranges, fingerprinting or codec behavior.

Printed pp.60-61 establish that Structures 2-10 combine a pair into Tone 2/4
and ignore Tone 1/3 output settings. The selected-Tone routing summary follows
that rule, distinguishes MIX/EFX/DIRECT, and identifies ignored effects sends.
Undocumented `<OUTPUT-2>` values are explicitly unknown. The processor overview has since been replaced by the branching configuration
graph described in `PHASE_4_EFFECT_ROUTING.md`.

The manual's fixed Chorus processor exposes Level, Rate, Depth, Pre-Delay,
Feedback and Output (p.64); it does not provide the decorative "Chorus 1" type
selector shown in the mockup. EFX-specific Parameter 1-12 byte-slot assignments
and raw-to-physical conversions are not established merely by reading the
effect control descriptions. Those controls remain explicitly raw pending
traceable mapping evidence. No mappings from another JV/XP model are substituted.

## Verification

Regression tests cover: explicit arming, 90 edits coalescing to one changed-byte
DT1, latest-value retention during read-back, safety-snapshot preservation,
byte-exact restoration, multi-byte parameter boundaries, payload limits,
Solo/Mute and A/B overlays, local-history preservation, mismatch termination,
pending-update cancellation, disconnect, and narrow-window audition controls.

Manual validation must additionally record audible response, sustained-control
drag latency, note tails under Solo/Mute, A/B switching, interruption during
update/read-back, and recovery without queued-write replay. No hardware behavior
has been promoted to HardwareVerified by this implementation.
